# Overview

my-journal is a monorepo with three top-level folders and a root `package.json` whose `dev` script starts the client and server together using `concurrently`.[^repo]

```
client/  React 19 + Vite + TypeScript
server/  Express 5 + TypeScript (ts-node, nodemon)
         Prisma 7 → PostgreSQL via @prisma/adapter-ppg (DATABASE_URL in server/.env)
shared/  empty
```

This is the codebase **before** the backend rewrite. The Express server will be replaced; see [Backend: Python + FastAPI](../decisions/backend-python-fastapi.md).

Only a small part of the [PRD](../product/prd.md) is built so far: a basic entry form and an unfinished schema. The schema has no tables yet for chunks, embeddings, observations, retrieval events or reflections. The root `README.md` describes the planned product, and it still says "Backend: Node.js".

# Client

* A single `App.tsx` with a plain HTML form (title, content, mood) that posts to `http://localhost:8080/entries/1`.
* `vite.config.ts` proxies `/api` to `http://localhost:5000`.

# Server

* `index.ts` creates an Express app, enables `express.urlencoded`, mounts `/entries` and listens on `PORT` (default 3000).
* `src/routes/entryRoutes.ts` defines `GET /`, `GET /:id`, `POST /:id`, `PUT /:id` and `DELETE /:id`. All handlers are empty stubs.
* `src/controllers/entryController.ts` is empty.

# Database schema

Defined in `server/prisma/schema.prisma`. Primary keys are UUIDs generated by `uuid_generate_v4()`.

| Table | Purpose | Notable columns |
|---|---|---|
| `users` | Accounts | `email` (unique), `password_hash` |
| `journal_entries` | Entries | `user_id`, `title`, `content`, `mood`, `is_private` (default true), `location` (JSON), `created_at`, `updated_at` |
| `tags` | Tag names | `name` (unique) |
| `journal_entry_tags` | Many-to-many join between entries and tags | composite key `(entry_id, tag_id)` |
| `media` | Attachments on an entry | `url`, `type`, `metadata` (JSON) |
| `sync_logs` | Records of syncing an entry to an outside service | `service`, `status`, `synced_at` |

All child tables cascade on delete. `server/prisma/seed.ts` fills the database with fake data from faker.

# Known issues

* The ports don't agree: the form posts to `:8080`, the Vite proxy targets `:5000` and the server defaults to `:3000`.
* The seed command uses `tsx`, which is not in `server/package.json`.
* The server doesn't parse JSON bodies (no `express.json()`).
* There is no AI code yet.
* There are no tests and no CI.
